I kept running into the same thing across Islamic applications: a hardcoded JSON file of the 99 Names of Allah. Copied from some blog, pasted into the project, rarely touched again. When the transliteration had an error or the Arabic was missing a character, every app that copied that file inherited the same defect. There was no single source of truth — just fragmented copies propagating mistakes.

I built this API to be that source. One endpoint, consistent structure: Arabic script, Latin transliteration, Indonesian meaning, standard ordering. Free, no authentication, hosted on Vercel so it loads quickly from Indonesian locations. If someone is building an Islamic app and needs Asma'ul Husna, they can hit this instead of bundling a stale JSON file.

I wrote it in Go with Fiber. At the time I was looking to get more comfortable with Go, and a small focused API seemed like the right size of project for that. Fiber keeps allocations low compared to the standard library, which matters at steady traffic. I added Prometheus and Grafana for observability — request counts, latency percentiles, error rates. Even a free API should tell you when something is wrong before users do.

## Endpoints

| Endpoint            | Method | Description                                |
| ------------------- | ------ | ------------------------------------------ |
| `/`                 | GET    | Get info about the API                     |
| `/api/all`          | GET    | Get all Asma'ul Husna                      |
| `/api/:urutan`      | GET    | Get specific Asma'ul Husna based on urutan |
| `/api/latin/:latin` | GET    | Get specific Asma'ul Husna based on latin  |

## Response Example

**Get all Asma'ul Husna**

Request:

```ts
fetch("https://asmaul-husna-api.vercel.app/api/all")
  .then((res) => res.json())
  .then((result) => console.log(result));
```

With `page` and `limit`

